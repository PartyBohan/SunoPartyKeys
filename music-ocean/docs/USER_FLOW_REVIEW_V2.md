# 音乐海洋 V2 验证记录

本轮将网页调整为音乐密码设备式创作工作台：深色机身、浅色实体琴键、录音运输控件、音符显示屏、风格触发垫、独立作品与对比区。保留中文/English 与其他 API 设置。

## 核心变化

- 每次提交先将原始 WAV、音符/力度/踏板和任务保存到 R2/D1，按 Sites 用户 ID 隔离。
- 推进任务使用数据库 CAS 领取与领取令牌，浏览器 API 请求通过 Web Locks 串行。Suno 付费创作始终使用任务固定的 idempotency_key；网络重试不会改请求参数。
- 上传会话 ID 与 audio-upload-complete 返回的音频 clip ID 分开处理。纯音乐使用 Cover，保留源音频联系；有人声仍使用描述与 reference_audio_ids。没有启用 Max Mode 或高级控制。
- 完整保存 clip_ids/clips。逐首合并结果，分批轮询所有未终结作品；单首失败不掩盖成功作品，缺失作品不会被当成完成。
- 原始旋律 A 与生成作品 B 使用互斥播放器；源录音使用本次提交的不可变副本。
- 分享卡由浏览器生成 1080×1440 PNG，包含固定场景、原始音符和 provider 实际返回的歌曲二维码/链接。仅用户主动导出；不扩大站点公开范围，不请求 Suno download 权限。
- 其他 API 的提交确认丢失时进入 submission_unknown，禁止自动重提；保存 endpoint/model 指纹，防止连接切换后误发。
- 3 个 8 秒背景循环由现有图片确定性制作，保持人物，轻微水波/光线变化；静音、内联播放，尊重减少动态偏好，可关闭，后台暂停。

## 已验证与限制

- TypeScript、生产构建通过。
- 18 项自动化测试通过，含真实 SQLite SQL 的 owner 隔离、源文件一致性、请求键冲突、并发领取、子作品丢失保护和其他 API 超时不自动重提。
- 本地浏览器实际录入 C4/E4/G4，得到 3 个音；登录后恢复草稿；未连接生成服务时打开设置。
- A/B 互斥播放和分享卡生成通过明确标注“本地测试夹具 · 非生成作品”的本地数据验证。夹具仅存在本地 D1/R2，不进入生产、部署包或源码。
- 三个 MP4 的实际媒体信息：8.000 秒、24fps、192 帧、H.264/yuv420p、无音轨。编码后的首尾帧一致；人物保护区逐帧检查，没有几何变形。
- 线上已保存原始 WAV、音符与任务，重载仍可恢复。旧任务确认 provider error: generation did not finish。新的 Cover 测试任务 676c6164-d48f-4527-8281-9cb0f077c406 已返回两首 complete，第一首真实链接 https://suno.com/song/d3933b54-5fc2-45f6-813f-6eed73d86f2c ，Suno 官网显示 1:31、V6-MINI，并显示对应源旋律关联。官方嵌入页已实测播放：91 秒时长，readyState 4，播放时间推进到 11.27 秒；发布后站内两首 iframe 实测 time=12.91/13.29、readyState=4；原句时长10.04秒，切换互斥。手机内第一首也正常播放到22.53秒。
- 未接实体音乐密码/普通 USB MIDI/BLE MIDI/实体 iPad，本轮不作硬件发布就绪声明。

## 播放方式修正

Suno 用户 OAuth 对 REST stream 的支持未得到验证，实测代理出现 502。已移除该路径。没有公共 audio_url 时使用服务提供的标准 Suno embed 页面；仅允许匹配当前 clip ID 的 suno.com/song 链接推导 iframe URL，其他服务及其他域名不能注入 iframe。切到原句时卸载 iframe，切回成品时暂停原句再挂载。没有声称同步对齐 A/B，也没有提取加密媒体或扩展下载权限。原始 WAV 补充了 HTTP Range 支持。

## 新用户复测修正

独立 localhost 存储会话录入 C4/E4/G4，得到3音、0.8秒。发现开始录音清除错误后，未登录提示会消失，而作品库尚未加载又让生成按钮永久禁用。已去除重复的 cloudReady 门槛，主操作在未登录状态明确显示“登录保存作品”，并保留登录提示；所有提交仍由服务端校验账户和服务连接，不能绕过保存任务及固定请求键。
